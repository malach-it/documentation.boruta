Boruta 0.13.0 strengthens identity and consent checks, adds search to the administration scope list, and introduces an optional Mnesia repository backend for the gateway. It also fixes several wallet, credential, CLI, and gateway issues.

:::note Open beta

Boruta is currently in an open beta phase. While it is mostly stable and parts of the project have undergone security assessments, it remains a work in progress. We encourage you to test Boruta in your own context and share feedback: production readiness depends on real-world use to uncover bugs and improve usability. Please also review the [General Terms and Conditions](https://github.com/malach-it/boruta-server/blob/master/GENERAL_TERMS_AND_CONDITIONS.md).

:::

## Identity and authorization security

This release addresses four security issues:

- Blocking or deleting a user now invalidates their browser sessions, authorization codes, and access tokens. The administration API also rejects bearer tokens belonging to blocked or deleted users.
- Password-reset and confirmation tokens are no longer exposed in new or retained request logs ([advisory](https://github.com/malach-it/boruta-server/security/advisories/GHSA-xr62-x93r-6qmf)).
- Users with a registered WebAuthn credential must authenticate with WebAuthn even when their identity provider does not enforce it ([advisory](https://github.com/malach-it/boruta-server/security/advisories/GHSA-pf3v-7cr4-cw64)).
- Required user consent is enforced before an authorization code is issued, including when an authenticated user revisits the authorization URL ([advisory](https://github.com/malach-it/boruta-server/security/advisories/GHSA-cqjw-835x-pg9j)).

## Optional gateway storage backend

The gateway now supports an opt-in `ecto3_mnesia` repository backend, including Mnesia table setup and cache updates. PostgreSQL remains the default. Existing gateway data needs a separate migration before switching backends; upgrading Boruta alone does not move that data.

The example Docker Compose configuration no longer includes the sidecar gateway. Published container images now include provenance attestations.

## Administration and decentralized identity

Administrators can search scopes by name or label. The query remains in the URL, so search results can be revisited or shared. Request, business event, and token dashboard date filters now use HTML forms. Invalid YAML configuration uploads return a bad request response, and the CLI accepts release-local paths for configuration files. Client forms also show the JWT authentication public key field for EC signing algorithms.

For decentralized identity flows, anonymous wallet authorization can proceed without user consent. Universal keys can be created for OAuth client ID token and verifiable credential signing. Credential status token resolution verifies tokens against client DIDs, and DID service HTTP requests trust the configured service hosts. Imported wallet credentials are encrypted in local storage.

The gateway also handles invalid TLS handshakes without stopping its HTTPS acceptors.

## Before upgrading

Boruta remains in beta during the `0.x` series, so releases may include breaking changes. Review the identity and consent changes above against your sign-in flows. If you plan to use the Mnesia gateway backend, arrange a separate migration for existing gateway data. Deployments using the example Docker Compose file should account for the removed sidecar gateway.

See the [complete changelog](https://github.com/malach-it/boruta-server/blob/master/CHANGELOG.md#0130---2026-10-21) for the full list of changes.
